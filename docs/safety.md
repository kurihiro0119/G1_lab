# 安全運用チェックリスト

## 毎回の実験前
- [ ] `make preflight` が `RESULT: OK`（WARN なら内容を確認して記録する）
- [ ] バッテリー残量が十分
- [ ] ロボットの周囲 2m に人・物が無い。床が平らで滑らない
- [ ] リモコンを手に持ち、ダンピング / 停止操作をすぐできる
- [ ] **低レベル (rt/lowcmd) を使う場合は吊り下げ架台に吊っている**
- [ ] 実験記録を `experiments/` に作成した（`experiments/TEMPLATE.md` をコピー）

## レイヤ別の注意
| 実行するもの | 必要な状態 | 注意 |
|---|---|---|
| `g1_state_*` / `g1_health_check` / `g1_audio_led` | どの状態でも可 | 指令を送らないので安全 |
| `g1_loco_cli` | 立位 or 吊り下げ | 速度は上限付き。`damp`/`zero` は立位だと崩れ落ちる |
| `g1_arm_action_cli` | 歩行制御中 (fsm 500) | 一部の動作は転倒の恐れがある (SDK コメントより)。解除は `release` |
| `g1_arm*_sdk_dds_example` | 歩行制御中 | 重みの上げ下げをゆっくり。腕の可動範囲に物を置かない |
| `g1_ankle_swing_example` / `g1_dual_arm_example` | **吊り下げ必須** | 起動時に Unitree の制御が止まり脱力する。終了後は再起動して戻す |

## 自作の低レベル制御を書くとき
- 最初は Kp を小さく、目標値は現在値から補間してゆっくり動かす
- 関節の角度上限・速度上限・トルク上限を自分のコードでもクリップする
- `rt/lowstate` が一定時間途絶えたら指令を止める（ウォッチドッグ）
- 実機の前に Docker でビルドを通し、ログを取りながら少しずつ振幅を上げる

## 異常時
1. リモコンでダンピング / 非常停止
2. Ctrl+C でプログラムを止める（`g1_loco_cli` は終了時に StopMove を送る）
3. 状況・ログ (`make fetch`) を実験記録に残す
